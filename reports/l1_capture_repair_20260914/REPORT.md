## 已确认的问题与原因边界

- 今天四股实时首条留存在美东 10:02:18～19，开盘 09:30～10:02 没有本地实时事件。10:17 曾观测到约 95 秒积压，后来追平。

- 原 launchd 配置是 Background；已改 Standard 并关闭低优先级 I/O。当前接通 AC、AC sleep=0；休眠或后台调度是否造成最初漏采，证据仍不足。
- 三源 NTP 在 2026-09-14T14:36:27.991936+00:00 的偏差中位数为 276.6ms，表示本机较慢。偏差随时间变化；负的 received_at−exchange timestamp 不能解读为负网络延迟。

## 已实施

1. 单独 writer 线程、有界队列和批量 flush，让接收循环有机会处理心跳。队列满时显式等待并记录背压；不静默跳过事件。
2. 观察、入队、写出和未完成计数分开；事件入队前固定观察时间和连接编号。正常停止排空已接受数据，10 秒 drain 超时明确标记不完整。launchd 退出宽限设为 30 秒。
3. SDK 回调观察时间与 socket/NIC 接收时间明确区分；原始时间戳不平移、不截断负差。内部排队延迟使用单调时钟。
4. 质量报告 schema v3 保留负时间差并计数。新增有界、只读 NTP 时钟探测；不修改系统时间。
5. 服务状态检查验证采集器实际命令和 PID 关系。可选 AC 睡眠断言默认关闭；本次没有更改全局电源设置。
