## 2. 原来的炒股逻辑到底是什么，哪里合理

本地默认配置指向 `price_volume_h1_g50`：最后训练日为 **2026-09-11**，使用 12 列量价特征，逐股 Ridge 预测下一根五分钟收益。模型股票是 MSTR/NVDA/SNDK/TSLA；实际交易取模型与自选股交集。线上可以通过环境覆盖产物，所以这不是对线上此刻配置或运行状态的认证。

```text
已完成五分钟行情 → 量价特征 → 每股预期收益
                              ↓
             预期收益 − 风险惩罚 − 调仓成本
                              ↓
          组合目标权重 → 整数股数 → 先减仓后增仓
                              ↓
               券商成交确认 → 持仓与账务
```

合理的部分：使用完整 K 线、预测与执行分离、统一组合预算、把成本纳入优化、确认成交后再计库存。优化器解决的是“如何分配预测”，不能凭空创造预测优势。

原页面上的所有 AI 模块并没有共同决定交易。旧 EMA/RSI 打分、许多研究模型、新闻、财报、Futu 和两周情绪模型，不能因为文件存在就认定已经进入默认下单路径。代码入口：[live_runner.py](../../backend/app/broker/live_runner.py)、[quant_policy.py](../../backend/app/quant_policy.py)、[research_execution.py](../../backend/app/broker/research_execution.py)。

| 数据 | 实际覆盖 | 能回答什么，不能回答什么 |

具体发现：

1. **高换手吞噬毛利。** 本轮 A 毛收益 $2,010.59，却消耗 $4,520.58 假设摩擦，发生 2,930 笔模拟成交。B 降到 890 笔，C 为 879 笔。成交笔数不等于完整往返交易次数。
2. **旧日志有负期望入场矛盾。** 9/11 的 60 条明确 BUY/SHORT 入场提交日志中，37 条同时记着 `E[PnL]<0`。这需要查对应旧版本；日志缺版本和稳定订单关联，不能冒充已证明现行 Ridge 存在同一个错误。`P_win<50%` 本身也不意味着交易必错，还要看盈亏幅度和成本。
3. **操作缺乏完整决策证据。** 很多操作没有原预测、模型版本、预期持有期及到达时报价，不能把每一笔亏损直接标为“方向判断错”。新回放已逐时点保存预测、文本证据、修正原因、模型训练记录和成交账本。
4. **成本导致部分毛赢变净亏。** 条件 FIFO 有 924 个匹配批次，单边 2/5/10 bps 假设分别吞掉 20/46/79 个毛盈利批次。因缺期初库存、完整费用与成交，且有同秒反向操作顺序不明，这些匹配不是已验证的账户 P&L。
5. **收益来源发生变化。** 本轮 A 的三股贡献为 NVDA −$366.73、SNDK +$733.25、TSLA −$2,876.50；B 为 NVDA +$656.12、SNDK −$427.43、TSLA −$280.14。不能看完结果只保留 NVDA 就声称找到了选股规律。

## 4. 新模型 B 具体改了什么

| 修改点 | 旧 A | 新 B（C 使用相同量价部分） | 要解决的问题 |
| --- | --- | --- | --- |
| 预测周期 | 下一根五分钟 | 固定未来 30 分钟；每五分钟仍可更新目标 | 检查较慢预测是否能覆盖执行摩擦；不是证明 30 分钟最优 |
| 更新方式 | 固定旧模型权重 | 每个历史决策日只用之前完整日期训练 | 避免一直使用旧产物；这次是离线逐日回放，尚非线上自动训练服务 |
| 预测幅度 | 直接使用模型输出 | 最近五个先前完整交易日作独立校准，学习 `[0,1]` 缩放系数 | 对过去失效/过强的预测减弱；系数为 0 时允许不新增仓位 |
| 防泄漏 | 旧冻结训练界限 | 基础模型不使用这五天校准数据；文本只用更早已成熟残差 | 不让用于检验的答案重新进入同一次训练 |
| 情绪接入 | 无 | 用当时真正收到的文本特征修正同一 30 分钟收益 | 测试文本对量价之外还有没有增量 |
| 缺数据 | 无文本能力 | 无合格文本或校准不足，精确回到 C | 不把未知当中性，不凭空生成买卖信号 |
| 执行和约束 | 原优化器、整股、收盘清仓 | 完全共用 | 不靠只给新模型加杠杆、允许隔夜或更好成交制造优势 |

量价实现：[sentiment_alpha_candidate.py](../../backend/app/research/sentiment_alpha_candidate.py)。文本实现：[quant_signal_adapter.py](quant_signal_adapter.py)。统一运行入口：[run_quant_sentiment_comparison.py](../../scripts/run_quant_sentiment_comparison.py)。

## 5. 这次真正用了哪些情绪 signal，如何变成交易输入

当前适配器是可审计的小型文本模型，不是已经微调好的大语言模型。它提取以下 **12 个数值特征**：新闻量、Futu 帖子量（对数）；两类各自的方向平衡和可判断比例；不同文本比例；发布时间年龄；收讫年龄；整体/新闻/Futu 缺失标记。

- 新闻关键词如升级/降级评级、bullish/bearish；Futu 关键词如看多/看空/买入/卖出。否定、条件、多公司归属和无方向信息要保留未知。当前简单词典不是可靠的复杂金融语义理解。
- 新闻/帖子必须有原文版本、来源 ID、发布时间、更新时间和可核对的实际收到时间。可用时点是三者最大值，再加 **60 秒模拟处理延迟**；这个延迟是回放假设，不是声称当时已实时运行。
- 只保留最近 **48 小时**的合格内容，旧文刚收到不能自动变成新事件。同 ID 的可用版本去重；不同标题比例只是重复文本代理，不是完整事件新颖度。
- 用过去结果拟合 `未来30分钟真实收益 − C的30分钟预测`，学习文本残差；每次修正限制在 **±5 bps**。上限是本次预登记工程参数，不是已证明最佳值。
- 文本校准至少需要 100 个有文本决策样本、5 个覆盖日期、合计 30 个按公司计的不重叠区间。**这些只是工程最低条件，不代表独立事件足够或统计显著。** 同一批文本能连续使用多天。
- 新闻两周收益不能直接加到五分钟/30 分钟预测，也不能简单除以天数或分钟数。临近收盘使用与量价相同的期限缩放。

**实际影响：**7,296 个“股票×决策时点”中，417 个有当时可用文本；其中 50 个预测被修改，对应 **10/23 的 25 个组合决策时点，涉及 NVDA 和 TSLA**。这些是预测修订次数，不是订单数。新适配器第一次达到校准门槛后，才允许产生非零修正。

本次新闻方向词特征在最终训练样本中没有有效变化；实际修正更多来自消息量、年龄、来源缺失及残差截距等结构。Futu 立场进入过训练，但没有证明“富途越看多越应该做空”。**B−C = −$84.07 衡量整个适配器，不能解释成纯情绪语义的独立因果效果。** 以后要增加同覆盖的常数残差、文本置乱及独立人工立场评价，才能区分信息量、偏差校准和语义贡献。

原有固定 FinBERT 推理、LM 词典、十日 TF-IDF 实验仍保留；本次没有把它们的分数强行混成一条“万能情绪分”。

**10/28 价格标签 BERT 已真正完成训练和评价。** 用官方固定版本 `google-bert/bert-base-uncased`，对 Agilent（股票代码 A，不是策略 A）、Amazon、Microsoft 各自重置模型，只更新最后编码层与回归头。272 次真实优化、154 行测试、3 家公司均完成；训练前后核验每家公司 181 个冻结参数张量不变、18 个可训练张量实际改变。总运行约 20.2 分钟。所有公司训练完毕后才读取测试特征；154 行预测全部写盘冻结后才读取测试收益标签。

| 公司 | 测试公司日 | 简单训练均值 MAE | 纯价格 MAE | 价格标签 BERT MAE | BERT 方向准确率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Agilent（A） | 28 | 5.6557 pp | 5.3556 pp | 5.6832 pp | 32.14% |
| Amazon（AMZN） | 61 | 3.2371 pp | 3.5316 pp | 2.7115 pp | 39.34% |
| Microsoft（MSFT） | 65 | 2.5281 pp | 2.4826 pp | 2.5896 pp | 69.23% |

MAE 越小越好，pp 是收益率的百分点。Amazon 的幅度误差改善，但方向准确率低于简单均值的 50.82%；Microsoft 的方向准确率与简单均值相同。不能把“模型训练完成”或单家公司指标改善当成已获得 Alpha。全部 9 个同样本模型及成本假设保存在[公开 BERT 结果](../../reports/financial_sentiment_price_bert.json)。每家公司只有 6/7/7 个不重叠评价区间；示意 long/cash 交易分别为 0/2/7 笔，不能用 154 行重叠预测冒充 154 笔独立交易。该实验是 2023 十日相对 SPY 价格收益研究，**不改变上面的 2026 日内 A/C/B 曲线**。

## 信号图怎么读

[静态信号图](../../reports/financial_sentiment_signal_explorer.png)与现有 Quant.ai 页面 **Financial Sentiment → Signal explorer** 使用同一份保存证据，共96个股票—日期切片、7,296个公司决策。可以选股票、日期和时点，逐项查看：

1. 完整价格柱、模拟买卖标记及已实现的模拟持仓。买入也可能是平空，不直接等于看多。
2. A的5分钟预测与B/C的30分钟预测分图展示，收盘前显示缩短后的有效期限。
3. 文本对预测的增量，及每个特征、截距、±5bps截断的算术分解；这是模型解释，不是价格因果归因。
4. 来源版本、发布时间、更新时间、真正收到时间和允许使用时间。默认打开最早有非零修正的切片，不按盈利挑例子。
5. 另行展开的后续实际价格收益，仅作为事后诊断，绝不能当成当时信号。

本轮可用证据实际上只有10/12与10/21两个独立收讫日期；“5个覆盖日期”不等于五次独立采集。例子中新闻可能仅因供应商股票标签关联到NVDA，标题主题却是Meta或SpaceX；因此有文本不等于有直接公司信息。未证明相关性和增量前，不把这些修正晋级交易。

## 8. 系统怎样放进 Quant.ai

```text
新闻/Futu/官方披露 ─→ 时间与版本证据 ─→ 公司/事件/立场/期限特征
                                           │
     两周趋势研究（独立任务）                │ 同周期残差校准
     未来5/10/20日 → 研究展示                 ▼
原量价输入 → 改进价格模型 C ─────────────→ 新候选 B
                     │                     │
                     └─ 同一组合优化/风控/模拟执行 ─┘
                                           ▼
旧 A ───────────────────────────→ 同资金比较与决策归因
                                           ▼
                      只读 JSON → 现有 Quant.ai React 页面
```

两周模型先提供公司中期背景；若将来允许两周持仓，需要独立的隔夜风险、账本和共同允许跨夜的价格基准。不能把原日内策略错过的隔夜涨幅算成已捕获收益。长期 20/60/120 日投资研究也是另一任务。

页面的 **Observed data coverage** 是回答“数据够不够、来自何时、漏了什么”，不应该充当收益成绩。本轮双模型页面直接给净值、成本、敞口、回撤和文本实际修订次数。原 `/status` 仍是旧审计契约，会固定显示 `Not trained`；它不代表现在所有研究都未训练。后续应按实验轨道升级状态，不能仅把 JSON 改成 `Trained` 绕过校验。

部署入口：[Quant.ai Financial Sentiment](https://ypeng12-quant-ai.hf.space/?tab=financial_sentiment)。本轮补上 `/comparison`、`/signals`、`/context` 路由及相应白名单快照；`/status` 和旧 `/report` 继续标明历史轨道。发布验收分别检查这几个接口、实际页面图表、部署 SHA 以及交易仍处于停止状态，不能只凭构建成功判断上线。

## 9. 仍需修复的执行问题，以及继续投入的判断标准

尚未解决的代码审计问题包括：数据/模型异常时保留库存，但默认普通市价入场并不自动建立保护单；模型只拒绝未来训练日期，没有完整过期验收；成本未由真实报价/到达/成交校准；服务隐式启动问题本轮已修复：构造/启动API均保持交易待命，只能显式开始；常规自动决策先存模型/数据哈希、预测、目标和订单意图，审计存储失败禁止新增风险但允许减仓；过期bar不能继续提交，定时清仓使用独立原因和关联ID。手动/延长时段路径尚未全部纳入同一journal。公开HF部署新增统一只读边界：所有API修改请求返回403，不能从公共网页启动交易或改配置；本地无SPACE_ID环境仍保留原控制。新的研究预览没有导入或启动交易服务。

不能用“接入了情绪”掩盖这些问题，也不能未经验证就添加固定止损、冷却或放大仓位。先补真实决策与执行证据，才能分清亏损来自预测、仓位、成本还是系统故障。

继续工作的门槛应是：

1. 明确原策略 A、候选 C/B、数据版本和实际交易规则，避免网页开关与真正使用模型不一致。
2. 连续留存可核对的消息、行情、决策和成交；来源断档必须显示，不能拿文章发布时间代替我们收到时间。
3. 未来冻结规则的 A/C/B 对照报告净收益、成本、回撤、实际风险、股间集中度，并扣除新增数据/推理费用。B 少亏不等于盈利；C 已解释的改善不算文本收益。
4. 首轮约 40 个交易日只是观察起点，不是稳定性保证。两周标签会重叠，40 天只有很少独立波段；不能根据有利结果提前停表。
5. 文本没有增量就禁用该修正作为正式候选；保留失败实验。复杂模型、更多接口、更多页面都不能替代经济净收益证据。

**当前判断：值得保留本轮代码与证据继续验证；没有依据增加真实交易风险，也没有依据承诺大额收益。** 这次没有按结果删除情绪的负贡献、挑掉 TSLA 或提高杠杆。多次尝试后只报告赢家会夸大策略表现，参见 [Bailey/Lopez de Prado 原论文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)；费用会直接侵蚀收益，参见 [SEC 投资者说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/updated)。
